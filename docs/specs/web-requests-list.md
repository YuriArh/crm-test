# Спека: экран списка заявок (реестр) во фронтенде

Статус: согласовано (14.11.2026), решения в §8. Основание: ТЗ D06, NF01, NF02, NF07; `docs/PLAN.md` §3 («Реестр заявок с
фильтром»); `docs/dispatch-design.md` §3 (срок и просрочка), §9 (реестр). Внешний вид — `docs/design-system.md`.

«Задачи» предметной области — заявки на доставку груза; в интерфейсе они называются **заявками**.
Сервер уже готов: `GET /api/requests` в `contracts/dispatch-api.yaml`. Контракт не меняется.

## 1. Зачем

Главный рабочий экран. Инициатор видит свои заявки и их судьбу: дошла ли до перевозчика, есть ли результат,
не просрочена ли. Оператор видит все заявки своей службы и быстро находит те, что требуют внимания: ошибки
отправки, неизвестный исход доставки, просрочку. С экрана переходят в карточку заявки.

Требования к виду: всё читается с первого взгляда (статус не только цветом, но и словом), экран работает
на телефоне от 360 px, а на десктопе вмещает много строк без шума.

## 2. Что можно сделать на экране

| Действие | Инициатор | Оператор |
|---|---|---|
| Видеть заявки | свои | все заявки своей службы |
| Фильтр «Результат» (`businessStatus`) | да | да |
| Фильтр «Доставка» (`deliveryStatus`) | нет (см. §4.3) | да |
| Переключатель «Только просроченные» (`overdue`) | да | да |
| Сортировка | да | да |
| Листать страницы по 20 | да | да |
| Открыть карточку заявки | да | да |
| Кнопка «Новая заявка» | да, когда появится экран создания | нет |

Права в UI — удобство. Область видимости задаёт сервер по сессии (NF02): параметров «чьи заявки» в запросе нет.

## 3. Данные

**Запрос:** `GET /api/requests?businessStatus=&deliveryStatus=&overdue=&page=&size=20&sort=`.
Ответ `RequestPage`: `items[]`, `page`, `size`, `totalElements`, `totalPages`.

**Поля строки (`RequestListItem`):** `number`, `cargoDescription`, `deadline` (дата в бизнес-зоне),
`businessStatus`, `deliveryStatus`, `overdue` (считает сервер), `owner`, `assignee` (может быть `null`),
`createdAt` (UTC).

**Состояние экрана живёт в адресе** — ссылку можно отправить коллеге, «Назад» возвращает прежний фильтр:

```
/requests?result=SUCCEEDED&delivery=FAILED&overdue=1&sort=deadline&page=2
```

| Параметр адреса | Значения | По умолчанию | В API |
|---|---|---|---|
| `result` | `AWAITING`, `IN_PROGRESS`, `SUCCEEDED`, `REJECTED` | нет (все) | `businessStatus` |
| `delivery` | значения `DeliveryStatus`; только для оператора | нет (все) | `deliveryStatus` |
| `overdue` | `1` | нет | `overdue=true` |
| `sort` | `new`, `old`, `deadline`, `number` | `new` | `createdAt,desc` / `createdAt,asc` / `deadline,asc` / `number,desc` |
| `page` | номер страницы с 1 | 1 | `page` − 1 |

- Значения по умолчанию в адрес не пишутся: чистый адрес `/requests` = все заявки, новые сверху.
- Неизвестные или чужие значения (`result=foo`, `delivery=…` у инициатора) отбрасываются при разборе адреса,
  экран не падает.
- Смена фильтра или сортировки сбрасывает страницу на первую.
- Если страница больше последней (заявок стало меньше), экран заменяет адрес на последнюю страницу.

**Кэш и обновление:** ключ запроса `['requests', 'list', параметры]`. При смене страницы или фильтра старые
строки остаются на экране, пока не придут новые (`placeholderData: keepPreviousData`), — без мигания.
Статусы меняются сами (обмен с перевозчиком идёт в фоне), поэтому список перезапрашивается раз в 10 секунд,
пока вкладка видима. При возврате на вкладку — сразу.

**Бизнес-зона:** даты показываются в зоне из `GET /api/system/info` (`businessTimezone`), а не в зоне
браузера (NF07). Запрос `system/info` кэшируется на всю сессию.

## 4. Как выглядит

### 4.1 Десктоп (≥ 62em ≈ 992 px): таблица

```
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│ ◆ Dispatch                                         Оператор (Север) · Север   ☀  Выйти   │
├──────────────────────────────────────────────────────────────────────────────────────────┤
│ Заявки  128                                                                               │
│                                                                                          │
│ [Результат: Все ▾] [Доставка: Все ▾] [○ Только просроченные]   ×Сбросить   Сортировка ▾  │
│                                                                                          │
│ Номер       Груз                     Срок          Результат     Доставка      Отв.     │
│ ──────────────────────────────────────────────────────────────────────────────────────── │
│ DR-000128   Паллеты с плиткой        01.12.2026    ● В работе    ● Получена    —        │
│ DR-000127   Холодильник, 2 шт.       ⚠ 12.11.2026  ● Ожидает     ● Повтор      Оператор │
│             (Инициатор (Юг))           просрочена                                        │
│ DR-000126   Документы                28.11.2026    ● Выполнена   ● Получена    —        │
│ …                                                                                        │
│                                                       1–20 из 128     ‹  1  2  3 … 7  ›  │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

- **Заголовок:** «Заявки» и рядом приглушённым числом `totalElements` с учётом фильтра. Справа кнопка
  «Новая заявка» (инициатор, когда есть экран создания).
- **Панель фильтров** в одну строку над таблицей: выпадающие списки «Результат» и «Доставка» с пунктом «Все»,
  переключатель «Только просроченные», ссылка «Сбросить» (видна, только когда есть активный фильтр),
  справа «Сортировка». Активный фильтр подсвечен акцентной рамкой — видно, что список сужен.
- **Колонки:**

  | Колонка | Содержимое | Кто видит |
  |---|---|---|
  | Номер | `DR-000128` моноширинным шрифтом | все |
  | Груз | описание, одна строка с многоточием, полный текст во всплывающей подсказке | все |
  | Автор | `owner.displayName` | оператор (инициатор видит только свои) |
  | Срок | `01.12.2026`; просроченный — красный, со значком и словом «просрочена» | все |
  | Результат | бейдж бизнес-статуса | все |
  | Доставка | бейдж статуса доставки | все (у инициатора упрощённый, §4.3) |
  | Ответственный | `assignee.displayName` или «—» | все |
  | Создана | время создания заявки (`createdAt`): `12.11, 12:15` в бизнес-зоне; год, если не текущий. По нему сортируются «новые» и «старые» | все |

- **Строки** высотой 40 px, разделители — граница `--app-color-border`, при наведении фон
  `--mantine-color-default-hover`. Вся строка — ссылка на карточку `/requests/{id}` (работают Ctrl+клик и
  «открыть в новой вкладке»).
- **Внизу:** «1–20 из 128» и пагинация. Страница прокручивается целиком, шапка таблицы прилипает к верху.

### 4.2 Телефон (< 62em): карточки

```
┌──────────────────────────────┐
│ ◆ Dispatch          ☀  Выйти │
├──────────────────────────────┤
│ Заявки  128                  │
│ [⚙ Фильтры · 2]  [Новые ▾]   │
│ ×В работе  ×Просроченные     │
│                              │
│ ┌──────────────────────────┐ │
│ │ DR-000127    ● Ожидает   │ │
│ │ Холодильник, 2 шт.       │ │
│ │ ⚠ до 12.11 · просрочена  │ │
│ │ ● Повтор отправки        │ │
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ DR-000126    ● Выполнена │ │
│ │ Документы                │ │
│ │ до 28.11 · Получена      │ │
│ └──────────────────────────┘ │
│        ‹   2 / 7   ›         │
└──────────────────────────────┘
```

- Таблица заменяется списком карточек (одна колонка, отступ 12 px). Карточка — ссылка на заявку:
  1. номер (моноширинный) слева, бейдж результата справа;
  2. груз — до двух строк, кегль 14 px;
  3. срок «до 12.11» и признак просрочки; у оператора — автор;
  4. статус доставки, если он не «Получена перевозчиком» (обычное состояние не шумит).
- **Фильтры** прячутся за кнопкой «Фильтры» с числом активных; она открывает нижнюю шторку (`Drawer`) с теми же
  полями и кнопками «Показать» / «Сбросить». Активные фильтры видны под кнопкой чипами с крестиком — снять
  фильтр можно в одно касание.
- **Сортировка** — компактный выпадающий список рядом с «Фильтрами».
- **Пагинация** компактная: «‹ 2 / 7 ›».
- Шапка приложения на телефоне (< 36em): блок с именем, ролью и службой скрыт, остаются знак, переключатель
  темы и «Выйти» — иначе шапка не помещается в 360 px.
- Касательные цели не меньше 40 px; горизонтальной прокрутки нет при ширине от 360 px.

### 4.3 Статусы: слова и цвета

Статус всегда показывается словом в бейдже с цветной точкой; цвет только дублирует слово.

| Результат (`businessStatus`) | Подпись | Цвет |
|---|---|---|
| `AWAITING` | Ожидает результата | серый |
| `IN_PROGRESS` | В работе | акцент |
| `SUCCEEDED` | Выполнена | зелёный |
| `REJECTED` | Отказ | красный |

| Доставка (`deliveryStatus`) | Оператор видит | Инициатор видит | Цвет |
|---|---|---|---|
| `PENDING` | В очереди | Отправляется | серый / акцент |
| `SENDING` | Отправляется | Отправляется | акцент |
| `RETRY_WAIT` | Повтор отправки | Отправляется | жёлтый / акцент |
| `UNKNOWN` | Неизвестно, получена ли | Отправляется | оранжевый / акцент |
| `ACKNOWLEDGED` | Получена перевозчиком | Получена перевозчиком | зелёный |
| `FAILED` | Ошибка отправки | Ошибка отправки | красный |

Инициатору технические подробности обмена не нужны, поэтому четыре промежуточных состояния для него — одно
«Отправляется». По той же причине у инициатора нет фильтра «Доставка»: «Отправляется» соответствует четырём
значениям, а API принимает одно.

Цвета берутся из темы (`gray`, `accent`, `green`, `red`, `yellow`, `orange`), бейдж `variant="light"`;
контраст проверяется в обеих схемах.

### 4.4 Состояния экрана

| Состояние | Что показываем |
|---|---|
| Первая загрузка | Скелет: 8 серых строк (на телефоне — 4 карточки), панель фильтров уже активна |
| Подгрузка новой страницы/фильтра | Старые строки остаются, тонкая полоска загрузки над таблицей |
| Заявок нет совсем | Инициатор: «Заявок пока нет» + «Новая заявка» (когда есть экран создания); оператор: «В службе пока нет заявок» |
| Фильтр ничего не нашёл | «Ничего не найдено» + кнопка «Сбросить фильтры» |
| Ошибка загрузки (сеть, 5xx) | Сообщение на месте таблицы и «Повторить»; если строки уже были — они остаются, сверху предупреждение |
| `401` | Общий обработчик: вход с возвратом на этот же адрес с фильтрами |
| `400` (сломанный адрес дошёл до API) | Сбросить параметры к значениям по умолчанию |

## 5. Устройство

```
src/requests/
  routes.tsx          /requests (validateSearch → RequestListSearch), / → redirect на /requests
  search.ts           разбор и запись параметров адреса ⇄ параметры API (чистые функции)
  api.ts              requestListQueryOptions(params), systemInfoQueryOptions
  statuses.ts         подписи и цвета статусов, упрощение доставки для инициатора
  format.ts           даты в бизнес-зоне (Intl.DateTimeFormat с timeZone), «1–20 из 128»
  RequestListPage.tsx экран: заголовок, фильтры, таблица или карточки, пагинация, состояния
  RequestFilters.tsx  панель фильтров (десктоп) и шторка (телефон)
  RequestTable.tsx    таблица (≥ md)
  RequestCards.tsx    карточки (< md)
  StatusBadge.tsx     бейдж статуса
```

- Маршрут `/requests` висит на `authenticatedRoute`; временная главная (`src/home/`) удаляется, `/` ведёт на
  `/requests`. После входа `safeNext` по умолчанию тоже ведёт на `/requests`.
- Загрузка через `loader` маршрута (`ensureQueryData`) — данные начинают грузиться до отрисовки; дальше экран
  читает тот же запрос через `useQuery`.
- Таблица или карточки выбираются CSS-ом (`visibleFrom="md"` / `hiddenFrom="md"`), а не JS-медиазапросом:
  без скачка разметки при загрузке.
- Компоненты Mantine: `Table` (со `stickyHeader`), `Select`, `Switch`, `Badge`, `Pagination`, `Drawer`, `Chip`/
  `Pill`, `Skeleton`, `Tooltip`. Цвета и размеры — только из темы и `--app-*`.
- Ссылка строки: строка таблицы — `<tr>` с ссылкой в ячейке номера, растянутой на всю строку (доступно с
  клавиатуры и для «открыть в новой вкладке»); карточка — целиком `<a>`.
- Пока нет экрана карточки, ссылки ведут на `/requests/{id}`, где будет «Не найдено». Карточка — следующая
  спека.

## 6. Тесты

**Unit (Node):** `search.ts` — разбор адреса (значения по умолчанию, мусор, `delivery` у инициатора), запись
адреса без значений по умолчанию, перевод в параметры API, сброс страницы при смене фильтра; `statuses.ts` —
подписи, упрощение для инициатора; `format.ts` — дата срока без сдвига зоны, `createdAt` в Москве на границе суток.

**Компонентные (jsdom + MSW):**
- строки из ответа: номер, груз, срок, бейджи; просроченная — со словом «просрочена»;
- выбор фильтра меняет адрес и параметры запроса, страница сбрасывается;
- инициатор: нет фильтра «Доставка» и колонки «Автор», доставка упрощена;
- пустой реестр, пустой результат фильтра со «Сбросить фильтры», ошибка с «Повторить»;
- пагинация: переход на страницу 2, номер страницы в адресе; страница за пределами → последняя;
- клик по строке ведёт на `/requests/{id}`.

**E2E (Playwright, против dev-сервера и стека):** данные создаются тестом через API с уникальным описанием
груза (адрес с «тест-отказ» даёт `REJECTED`), тесты не опираются на общее число заявок.
- инициатор видит свою новую заявку первой; заявки другого инициатора не видит;
- фильтр «Результат: Отказ» показывает отклонённую заявку и не показывает выполненную; адрес с фильтром
  открывается напрямую и после перезагрузки;
- оператор видит заявки обоих инициаторов своей службы и колонку «Автор»;
- телефон (390×844): карточки вместо таблицы, шторка фильтров, нет горизонтальной прокрутки;
- статус меняется сам: новая заявка через несколько секунд из «Ожидает» становится итоговой без перезагрузки.

Проверка глазами: обе схемы, 1280 px и 390 px (скриншоты, как для экрана входа).

## 7. Порядок работ

Каждый шаг заканчивается зелёными `make web-build` и `make web-e2e`.

1. **Маршрут и данные:** `/requests`, редирект с `/`, `search.ts`, `api.ts`, `format.ts`, `statuses.ts`.
   Unit-тесты.
2. **Таблица (десктоп):** заголовок, таблица, бейджи, пагинация, состояния загрузки/пусто/ошибка.
   Компонентные тесты; e2e «инициатор видит свою заявку».
3. **Фильтры и сортировка:** панель, адрес, сброс. Компонентные тесты; e2e фильтра и прямой ссылки.
4. **Телефон:** карточки, шторка фильтров, чипы. E2E на 390 px.
5. **Автообновление** раз в 10 с; e2e «статус меняется сам».
6. **Документация:** CLAUDE.md (модуль `requests`), README; удалить `src/home/`.

## 8. Принятые решения (14.11.2026)

1. **Сортировка «по сроку»** — ближайшие сроки сверху (`deadline,asc`), обратной нет.
2. **Автообновление раз в 10 секунд**, пока вкладка видима; кнопки «Обновить» нет.
3. **Поиск** по номеру или грузу и фильтр «Назначенные мне» — на этапе 2 (нужны параметры в контракте и
   индексы).
4. **Одно значение на фильтр**, как в контракте.
5. **Колонка «Создана»** (время создания заявки) — у всех, на десктопе.

Создание и карточка заявки (с правкой) описаны в `docs/specs/web-request-form.md`; кнопка «Новая заявка» и
ссылки строк ведут на эти экраны.
