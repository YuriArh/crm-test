# Спека: авторизация во фронтенде (`web/`)

Статус: реализовано (14.11.2026), отличия от плана — в §7. Основание: ТЗ NF02, D06; `docs/PLAN.md` §3 («Вход»).
Серверная часть готова и не меняется: `contracts/dispatch-api.yaml` (`/api/auth/csrf`, `/login`, `/logout`, `/me`).
Транспорт (CSRF, ошибки) уже есть в слое данных `web/src/shared/api/`.

## 1. Зачем

Пользователь входит под демо-учётной записью, видит, кто он, и выходит. Все будущие экраны открываются только
после входа и получают текущего пользователя без отдельного запроса. Потеря сессии (выход в другой вкладке,
перезапуск `dispatch`) приводит на страницу входа с возвратом туда, где пользователь был.

Права в UI — только удобство: скрыть то, что всё равно запрещено. Ограничения обеспечивает сервер (NF02);
фронтенд не делает выводов о доступе, которых нет в ответах API.

## 2. Поведение

| Ситуация | Что видит пользователь |
|---|---|
| Открыл любой защищённый адрес без сессии | Страница входа; после входа — исходный адрес |
| Открыл `/login`, уже войдя | Переход на `next` или на главную |
| Неверный логин или пароль (`401 BAD_CREDENTIALS`) | Одно сообщение «Неверный логин или пароль», поле пароля очищается |
| Пустые поля (`400 VALIDATION_FAILED` или проверка формы) | Ошибки под полями |
| Нет связи, `5xx` при входе | Сообщение над формой, форма не сбрасывается |
| Вошёл | Шапка с именем, ролью и службой, кнопка «Выйти» |
| Нажал «Выйти» | Страница входа; кэш данных очищен |
| Сессия потеряна, любой запрос ответил `401 UNAUTHENTICATED` | Страница входа с `next` = текущий адрес |
| `GET /api/auth/me` при старте ответил `5xx` или нет сети | Экран ошибки с кнопкой «Повторить», а не страница входа |
| Неизвестный адрес | Страница «Не найдено» (заодно убирает предупреждение роутера) |

Тексты интерфейса на русском.

## 3. Устройство

### 3.1 Модуль `src/auth/`

```
src/auth/
  api.ts            meQueryOptions, useLogin, useLogout
  session.ts        clearSession(queryClient), onUnauthenticated: очистка + переход на вход
  safeNext.ts       безопасный путь возврата из ?next=
  guards.ts         requireAuth (beforeLoad), requireRole
  useCurrentUser.ts текущий пользователь внутри защищённой части
  LoginPage.tsx     форма входа
  routes.tsx        маршруты модуля: /login и защищённый layout
```

Модули импортируют из `@/auth` только `useCurrentUser`, `requireRole` и защищённый layout-маршрут, к которому
вешают свои маршруты.

### 3.2 Текущий пользователь

- `meQueryOptions`: ключ `['auth', 'me']`, `GET /api/auth/me`; `401` → `null` (не ошибка), прочие сбои →
  ошибка. `staleTime: Infinity`: пользователь меняется только через вход и выход, которые сами пишут в кэш.
- Источник истины — кэш TanStack Query. Отдельного стора (Context, Zustand) нет.
- `useCurrentUser()` возвращает `Me` и работает только внутри защищённой части: берёт пользователя из
  контекста маршрута, который заполнил `requireAuth`. Так экраны не видят `null` в момент выхода, пока
  роутер ещё не ушёл со страницы.

### 3.3 Маршруты и защита (TanStack Router)

```
__root__
├─ /login                    публичный; search: { next?: string }
└─ _authenticated (layout)   beforeLoad: requireAuth → context.me; компонент: AppShell + <Outlet/>
   └─ /                      временная главная (до модуля заявок)
```

- `requireAuth` в `beforeLoad`: `queryClient.ensureQueryData(meQueryOptions)`. `null` →
  `throw redirect({ to: '/login', search: { next: location.href } })`. Иначе возвращает `{ me }` в контекст.
- `/login` в `beforeLoad`: если пользователь уже есть → `redirect` на `safeNext(next)`.
- `safeNext`: только локальный путь (`/…`, не `//…`, не `/login…`), иначе `/`. Защита от открытого редиректа.
- `requireRole(me, role)`: для будущих экранов только для операторов. Чужая роль → `notFound()`, так же как
  сервер отвечает `404` на чужое.
- `defaultNotFoundComponent` и `defaultErrorComponent` в роутере.

### 3.4 Вход и выход

- `useLogin`: `POST /api/auth/login` через `unwrap`. При успехе удаляет из кэша все запросы, кроме `me`
  (данные прошлого пользователя не должны просочиться), кладёт ответ в `me`, затем `router.invalidate()` и
  переход на `safeNext(next)`. CSRF-токен после входа меняется — слой данных читает cookie перед каждым
  вызовом, отдельно ничего делать не нужно.
- `useLogout`: `POST /api/auth/logout`. В `onSettled` (и при ошибке тоже — локальная сессия всё равно
  заканчивается): очистка кэша, `me = null`, переход на `/login`. Cookie `XSRF-TOKEN` сервер удалил;
  следующий изменяющий вызов слой данных сам получит новый токен.
- Повторный клик по «Войти» во время запроса заблокирован (`loading` на кнопке).

### 3.5 Потеря сессии

- `QueryCache.onError` и `MutationCache.onError` в `createQueryClient` вызывают переданный обработчик для
  `ApiError` с `code = UNAUTHENTICATED`.
- Обработчик собирается в `src/app/` (там есть и роутер, и query client — без циклических импортов):
  очищает кэш, ставит `me = null`, переходит на `/login?next=<текущий адрес>`. Повторные `401` от
  параллельных запросов переход не дублируют.
- `401` самого `GET /api/auth/me` обработчик не вызывает: там это нормальный ответ «никто не вошёл».

### 3.6 Интерфейс

- Форма входа: Mantine `TextInput`, `PasswordInput`, `Button`, `Alert`; состояние формы — `@mantine/form`
  (новая зависимость; Zod не нужен — правило одно: поля не пустые). Ошибки сервера по полям
  (`fieldErrors`) показываются под полями.
- Подсказка с демо-логинами на странице входа (стенд демонстрационный, пароль общий).
- `AppShell` (Mantine): шапка с названием, `displayName`, ролью («Инициатор» / «Оператор»), службой и кнопкой
  «Выйти». Навигация появится вместе с модулями.

## 4. Тесты

**Unit (Vitest, без DOM):** `safeNext` (локальный путь, `//evil`, `/login`, пусто); обработчик `401`
(очищает кэш, один переход на несколько ошибок, не реагирует на `me`); `requireAuth` и редирект `/login` на
роутере с memory history и подставленным query client.

**Компонентные (Vitest + Testing Library + jsdom, MSW вместо dispatch):** форма входа — успех, `BAD_CREDENTIALS`,
пустые поля, сетевая ошибка, блокировка повторной отправки. Новые dev-зависимости: `@testing-library/react`,
`@testing-library/user-event`, `jsdom`, `msw`.

**E2E (Playwright, `e2e/auth/`, против dev-сервера и стека на :3000):**
- вход `north.initiator` → в шапке имя и служба;
- неверный пароль → сообщение, остаёмся на `/login`;
- глубокая ссылка без сессии → вход → возврат на неё;
- `/login?next=https://evil.example` → после входа главная;
- выход → `/login`; «Назад» в браузере не показывает защищённую страницу;
- потеря сессии: удалить cookie `JSESSIONID` → следующее действие уводит на вход с `next`;
- вход другим пользователем после выхода не показывает данные прошлого (проверяется, когда появятся данные).

Тесты создают свои данные и проходят повторно на непустой БД.

## 5. Порядок работ

Каждый шаг заканчивается зелёными `make web-build` и `make web-e2e`.

1. **Каркас маршрутов:** корневой маршрут с not-found и error-компонентами, публичный `/login` (заглушка),
   layout `_authenticated` с временной главной. Unit-тест роутера.
2. **Текущий пользователь и защита:** `meQueryOptions`, `requireAuth`, `safeNext`, `useCurrentUser`; экран
   ошибки при сбое `me`. Unit-тесты; e2e «глубокая ссылка без сессии → /login?next=…».
3. **Форма входа:** `@mantine/form`, `useLogin`, сообщения об ошибках, возврат по `next`. Настройка
   Testing Library + jsdom + MSW; компонентные тесты; e2e входа и открытого редиректа.
4. **Шапка и выход:** `AppShell`, `useLogout`. E2E выхода.
5. **Потеря сессии:** обработчик `401` в `createQueryClient`, сборка в `src/app/`. Unit-тест; e2e с удалением
   `JSESSIONID`.
6. **Документация:** раздел `web/` в `CLAUDE.md` (модуль `auth`, правило «права в UI — только удобство»),
   README (вход в веб-клиент, демо-пользователи).

## 6. Решения на согласование

1. **Форма:** `@mantine/form` без Zod. Альтернатива — React Hook Form + Zod (как в старом клиенте); для одной
   формы входа избыточно, но для формы заявки может пригодиться. Предлагаю `@mantine/form` и вернуться к
   вопросу на форме заявки.
2. **Главная после входа:** временная страница `/` с приветствием, пока нет реестра; потом `/` ведёт на реестр.
3. **Подсказка с демо-логинами** на странице входа — показывать всегда (стенд демонстрационный).
4. **Синхронизация вкладок** (выход в одной вкладке сразу разлогинивает другие через `BroadcastChannel`) — не
   делаем: вторая вкладка узнает о выходе на первом же запросе (`401`). Можно добавить позже.

## 7. Отличия реализации от плана

- `requireRole` не сделан: экранов только для операторов пока нет. Появится вместе с первым таким экраном.
- Шапка и выход живут в `src/auth/AuthenticatedLayout.tsx`, а не в `src/app/`: им нужны `useCurrentUser` и `useLogout`.
- Выход переходит на `/login` без `replace`: «Назад» возвращает на защищённый адрес, и его снова останавливает
  `requireAuth`. С `replace` «Назад» уводил со стенда совсем.
- Связка query client и роутера вынесена в `src/app/createApp.ts`: её используют и `main.tsx`, и тесты.
- E2E «потеря сессии → следующее действие → вход с `next`»: экранов с данными ещё нет, поэтому в e2e следующим
  действием служит выход (и перезагрузка страницы), а переход с `next` после любого `401` проверяет компонентный
  тест `src/app/sessionLost.test.tsx`. Полный e2e — с первым экраном данных.
- Защита от повторной отправки формы — блокировка кнопки: форма с заблокированной кнопкой отправки не
  отправляется и по Enter, отдельная проверка в коде не нужна (проверено тестом).
