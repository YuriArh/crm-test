# План: экран списка заявок

Спека: `docs/specs/web-requests-list.md` (согласована 14.11.2026). Внешний вид: `docs/design-system.md`.
Ветка: `web-init`. Порядок экранов: **список → карточка → создание** (`web-request-card-plan.md`,
`web-request-create-plan.md`).

## 0. Исходное состояние и правила

- Есть: авторизация (`src/auth/`), слой данных (`src/shared/api/`), дизайн-система (`src/app/theme/`), временная
  главная `src/home/` («Здравствуйте, …»).
- Сервер готов: `GET /api/requests` (фильтры `businessStatus`, `deliveryStatus`, `overdue`, `page`, `size`,
  `sort`), `GET /api/system/info` (бизнес-зона). Контракт не меняется.
- Каждый шаг — отдельный коммит; перед коммитом зелёные `make web-build` и `make web-e2e` (после
  `docker compose up -d --build web`). Компоненты Mantine подбираются и настраиваются по Mantine MCP.
- Визуальная проверка в конце шагов 2 и 4: скриншоты обеих схем, 1280 и 390 px.

## Шаг 1. Данные экрана (без интерфейса)

**Что делаем**
- `src/requests/search.ts` — тип состояния адреса (`result`, `delivery`, `overdue`, `sort`, `page`), разбор
  адреса с отбрасыванием мусора и значений по умолчанию, перевод в параметры API, сброс страницы при смене
  фильтра, число активных фильтров.
- `src/requests/statuses.ts` — подписи и цвета бизнес-статусов и статусов доставки, упрощение доставки для
  инициатора (§4.3 спеки), признаки итоговых состояний.
- `src/requests/format.ts` — срок без сдвига зоны (`01.12.2026`, `01.12`), время в бизнес-зоне
  (`12.11, 12:15`, год — если не текущий), «1–20 из 128».
- `src/shared/system.ts` — запрос `system/info` (кэш на сессию) и `useBusinessTimezone()`.
- `src/requests/api.ts` — ключи запросов, `requestListQueryOptions` (старые строки на время загрузки,
  обновление раз в 10 с, сразу при возврате на вкладку).

**Тесты (unit):** разбор и запись адреса, параметры API (у инициатора нет `deliveryStatus`), сортировки,
сброс страницы; подписи статусов для обеих ролей; даты на границе суток в Москве, год, диапазон.

**Готово, когда:** модули покрыты тестами; интерфейс не меняется, e2e как были.

## Шаг 2. Маршрут и таблица (десктоп)

**Что делаем**
- `src/requests/routes.tsx` — маршрут `/requests` под `authenticatedRoute` (`validateSearch`, `loaderDeps`,
  `loader` с `ensureQueryData`); `/` перенаправляет на `/requests`. Регистрация в `src/app/router.tsx`.
- Удаляем `src/home/`; `safeNext` по умолчанию по-прежнему `/` (он ведёт на список).
- `RequestListPage.tsx` — заголовок «Заявки» с числом, таблица, пагинация, «1–20 из 128».
- `RequestTable.tsx` — колонки по §4.1 (Автор — только оператору), строка-ссылка на `/requests/{id}`
  (ссылка в ячейке номера растянута на строку), липкая шапка.
- `StatusBadge.tsx` — бейдж «точка + слово», цвета темы.
- Состояния: скелет при первой загрузке, полоска при подгрузке, пустой реестр (разный текст для ролей),
  ошибка с «Повторить», страница за пределами → замена адреса на последнюю.
- Обновить тесты, которые ждали «Здравствуйте, …» после входа: `LoginPage.test.tsx`, `AuthenticatedLayout.test.tsx`,
  `sessionLost.test.tsx`, `router.test.ts`, e2e `auth/guard`, `auth/login`, `auth/logout`, `auth/session-lost`
  — теперь после входа виден заголовок «Заявки».

**Тесты**
- Компонентные (MSW): строки из ответа, бейджи, «просрочена»; инициатор без колонки «Автор»; пустой реестр;
  ошибка и «Повторить»; переход на страницу 2 (номер в адресе); страница за пределами; клик по строке.
- E2E: хелпер `e2e/requests/helpers.ts` — создание заявки через API (`Idempotency-Key`, уникальный груз);
  инициатор видит свою новую заявку первой и не видит заявку другого инициатора; оператор видит заявки обоих
  инициаторов своей службы и колонку «Автор».

**Готово, когда:** после входа открывается реестр; тесты зелёные; скриншоты обеих схем на 1280 px.

## Шаг 3. Фильтры и сортировка

**Что делаем**
- `RequestFilters.tsx` (десктоп): «Результат», «Доставка» (только оператор), «Только просроченные»,
  «Сбросить» (виден при активных фильтрах), «Сортировка». Активный фильтр подсвечен.
- Любое изменение пишет адрес через `navigate({ search })` со сбросом страницы.
- Пустой результат фильтра: «Ничего не найдено» и «Сбросить фильтры».
- `400` от API при сломанном адресе → сброс к значениям по умолчанию.

**Тесты**
- Компонентные: выбор фильтра меняет адрес и параметры запроса, страница сбрасывается; у инициатора нет
  «Доставки»; «Сбросить»; пустой результат.
- E2E: создать выполненную и отклонённую заявку (адрес с «тест-отказ»), дождаться итога; фильтр «Отказ»
  показывает отклонённую и не показывает выполненную; адрес с фильтром открывается напрямую и после
  перезагрузки; «Назад» возвращает прежний фильтр.

**Готово, когда:** фильтры и сортировка работают от адреса и в адрес.

## Шаг 4. Телефон

**Что делаем**
- `RequestCards.tsx` — карточки вместо таблицы ниже `md` (переключение `visibleFrom`/`hiddenFrom`, без
  JS-медиазапроса).
- Кнопка «Фильтры · N» и нижняя шторка (`Drawer`) с теми же полями, «Показать» и «Сбросить»; чипы активных
  фильтров с крестиком; компактная сортировка и пагинация «‹ 2 / 7 ›».
- Шапка приложения ниже 36em: скрыть блок с именем, ролью и службой (`AuthenticatedLayout`).

**Тесты**
- Компонентные: снятие фильтра чипом; шторка применяет фильтры.
- E2E (390×844): карточки вместо таблицы, шторка фильтров, нет горизонтальной прокрутки
  (`scrollWidth <= clientWidth`), касательные цели не меньше 40 px.

**Готово, когда:** экран удобен на 360–390 px; скриншоты обеих схем на 390 px.

## Шаг 5. Автообновление

**Что делаем**
- Проверить и при необходимости доработать обновление раз в 10 с: только при видимой вкладке, без мигания,
  без сброса прокрутки и фокуса.

**Тесты**
- Компонентные (поддельные таймеры): второй запрос через 10 с; на скрытой вкладке запросов нет.
- E2E: новая заявка без перезагрузки меняет «Ожидает результата» на итоговый статус.

**Готово, когда:** статусы в списке меняются сами.

## Риски

- **Данные в e2e:** реестр общий и растёт; тесты ищут свои заявки по уникальному грузу и не считают строки.
  Новые заявки первыми на первой странице только при сортировке «новые» — тесты фильтров создают заявки
  непосредственно перед проверкой.
- **Время исполнения у эмулятора:** итог приходит за 1–3 с, при очереди дольше; e2e ждут через
  `expect.poll`/`toHaveText` с таймаутом, а не фиксированной паузой.
- **Режимы сбоев эмулятора** (появились в `main`) могут быть включены вручную и сломать e2e — перед прогоном
  `make fault-off` (после слияния `main`).
- **Слияние с `main`:** в `main` менялись `CLAUDE.md` и `Makefile`; слить до шага 6, чтобы документация
  легла поверх.
